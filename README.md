# flight-monitor

Telegram-бот [@provozhaem_elyu_bot](https://t.me/provozhaem_elyu_bot): следит за рейсом на табло аэропорта Пулково —
[вылета](https://pulkovoairport.ru/passengers/departure/) или [прилёта](https://pulkovoairport.ru/passengers/arrival/) —
и присылает изменения статуса и строки рейса всем подписчикам.

По умолчанию — рейс **WZ 709 25.09 в 07:40, Санкт-Петербург → Батуми** (Red Wings).
Владелец может сменить рейс и дату командой `/flight`.

Бот рассчитан на поездки на несколько дней: его включают под поездку и он сам
останавливается, когда Эля вернулась (см. «Автоостановка»).

## Новая поездка

1. Включить бота:
   ```sh
   gh workflow enable monitor.yml -R alxch/flight-monitor
   gh workflow run monitor.yml -R alxch/flight-monitor
   ```
2. Отправить боту рейс туда: `/flight <номер> <дата>`, например `/flight WZ 709 25.09`.
   Подписчики остаются с прошлой поездки; новым друзьям — ссылка https://t.me/provozhaem_elyu_bot.
3. После вылета — рейс обратно: `/flight <номер> <дата>` (через сутки бот напомнит).
4. После прилёта бот сам остановится. Выключить раньше: `gh workflow disable monitor.yml -R alxch/flight-monitor`.

## Бот

Команды для всех: `/start` — подписаться, `/stop` — отписаться. На любое другое сообщение бот отвечает текущим статусом.

Команды владельца (`TELEGRAM_CHAT_ID`; в меню видны только ему):

- `/flight WZ 710 28.09` — сменить рейс и дату; `/flight WZ 710` — ближайший рейс; `/flight` — текущий рейс и справка.
  Дата: `28.09`, `28.09.2026`, `2026-09-28`, `сегодня`, `завтра`.
- `/subscribers` — список подписчиков с именами и username (отписавшихся в нём нет).

Владелец подписан с самого начала и получает «👤 Новый подписчик: Имя (@username)» при каждой новой подписке.

### Направление: провожаем или встречаем

Рейс ищется на обоих табло. Рейс из Петербурга — «Провожаем Элю ✈️ Санкт-Петербург → Батуми»,
в Петербург — «Встречаем Элю ✈️ Батуми → Санкт-Петербург». Для вылета бот сообщает о регистрации, выходе,
посадке, задержках и вылете; для прилёта — о вылете из пункта отправления, задержках, прилёте и ленте выдачи багажа.

После вылета (или прилёта) бот присылает финальное сообщение и больше не проверяет табло,
но продолжает работать и принимать `/flight`.

**Будильник при задержке или отмене.** Если рейс получил статус «Задержан», расчётное время
сдвинулось на более позднее или рейс отменён, бот присылает «🚨 Рейс … задержан! Вылет ожидается в …»
с кнопкой «✅ Понятно» — каждую минуту, 10 раз, пока подписчик не нажмёт кнопку. Каждый повтор
заменяет предыдущий (в чате одно сообщение, звук уведомления — каждый раз). Кнопка останавливает
повторы только для нажавшего.

**Автоостановка** (чтобы не держать GitHub Actions включённым без дела): бот останавливается сам и
отключает workflow, когда завершился рейс в Петербург («Встречаем Элю» — задача выполнена) или
когда после завершённого рейса 5 дней не было `/flight` (через сутки бот напоминает владельцу поставить обратный рейс). Владельцу приходит «🛑 Бот остановлен».
Включить снова: `gh workflow enable monitor.yml` и `gh workflow run monitor.yml`.

При смене рейса подписчики получают «🔄 Теперь слежу за рейсом …». Если рейса ещё нет на табло
(оно показывает только сегодня и завтра), бот сообщит, когда он появится.

### Тексты

- **Вводный текст** («Провожаем Элю ✈️ … Я слежу за рейсом…») — только в описании бота,
  в сообщения он не вставляется. Ответы короткие: подписка, текущий статус, команда.
- **Дата рейса** указывается везде, где упоминается номер рейса: «WZ 709 25.09 в 07:40, Санкт-Петербург → Батуми».
  Дата и время берутся из данных табло.
- **Профиль бота** обновляется скриптом автоматически под текущий рейс и направление:
  имя («Провожаем Элю · WZ 709 25.09 → Батуми»), короткое описание (превью ссылки)
  и описание «What can this bot do?» со строкой «Сейчас: <статус> (на ЧЧ:ММ МСК)».
- Вручную (через Bot API) заданы только аватар — самолёт без номера рейса — и меню команд.
- Названия городов не склоняются («Санкт-Петербург → Батуми»), чтобы тексты были правильными для любого рейса.
  Имя «Элю» задано константой `PERSON` в `monitor.mjs`.

## Как устроено

- **Данные:** JSON API табло `https://pulkovoairport.ru/api/?type=departure|arrival&when=0|1`
  (все рейсы за сегодня/завтра по Москве; параметр `col` — только ближайшие N рейсов, не используется).
  Статусы вылета считаются так же, как на сайте: «Регистрация 27-32», «Идет посадка», «Отправлен в …».
- **Запуск:** GitHub Actions. Каждый запуск работает ~9 минут: слушает команды бота (long polling)
  и проверяет табло раз в минуту. В конце запуск сам ставит следующий в очередь (`workflow_dispatch`).
  Cron каждые 5 минут — запасной вариант (GitHub выполняет его с задержками).
  Ручной запуск: `Actions → Flight monitor → Run workflow`.
- **Состояние** хранится в `state.json` и коммитится только при изменениях: текущий рейс,
  настройка из `/flight`, подписчики. Подписчики зашифрованы (AES-256-GCM, ключ выводится из токена бота);
  после смены токена они начинаются заново (остаётся только владелец).

## Настройка

Секреты репозитория:

```sh
gh secret set TELEGRAM_TOKEN
gh secret set TELEGRAM_CHAT_ID   # владелец
```

Необязательные переменные репозитория (`gh variable set ...`) — рейс по умолчанию, пока не задан через `/flight`:

- `FLIGHT_NUMBER` — номер рейса, по умолчанию `WZ 709`;
- `FLIGHT_DATE` — дата `YYYY-MM-DD` по Москве; если не задана, отслеживается ближайший рейс.

## Локальный запуск

```sh
DRY_RUN=1 node monitor.mjs   # одна проверка, сообщения печатаются вместо отправки
```

Нужен Node.js 18+, зависимостей нет.
