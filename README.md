# flight-monitor

Telegram-бот [@provozhaem_elyu_bot](https://t.me/provozhaem_elyu_bot): следит за рейсом
на [табло вылета Пулково](https://pulkovoairport.ru/passengers/departure/?when=0)
и присылает изменения статуса и строки рейса всем подписчикам.
После вылета рейса бот присылает финальное сообщение и больше не проверяет табло.

## Бот

Команды: `/start` — подписаться, `/stop` — отписаться. На любое другое сообщение бот отвечает текущим статусом.
Владелец (`TELEGRAM_CHAT_ID`) подписан с самого начала и получает «👤 Новый подписчик: …» при каждой новой подписке.

Договорённости по текстам:

- **Вводный текст** («Провожаем Элю в Батуми ✈️ Я слежу за рейсом…») — только в описании бота,
  в сообщения он не вставляется. Ответы короткие: подписка, текущий статус, команда.
- **Дата рейса** указывается везде, где упоминается номер рейса: «WZ 709 25.09 в 07:40, Санкт-Петербург → Батуми».
  Дата и время берутся из данных табло, а не задаются вручную.
- **Описание бота** («What can this bot do?», видно в пустом чате до Start) содержит строку
  «Сейчас: <статус> (на ЧЧ:ММ МСК)» и обновляется скриптом автоматически при каждом изменении статуса.

Профиль, который задаётся вручную через Bot API (скрипт его не меняет):

| Поле | Метод | Значение |
|---|---|---|
| Имя | `setMyName` | Провожаем Элю · WZ 709 25.09 → Батуми |
| Короткое описание (превью ссылки, профиль) | `setMyShortDescription` | Провожаем Элю в Батуми ✈️ Рейс WZ 709, 25.09 07:40 из Пулково — статус с табло аэропорта |
| Меню команд | `setMyCommands` | `start` — Подписаться на уведомления, `stop` — Отписаться |
| Аватар | `setMyProfilePhoto` | белый взлетающий самолёт на сине-бирюзовом градиенте, подпись «WZ 709» |

При смене рейса или даты эти поля нужно обновить вручную, как и строку «Провожаем Элю в Батуми» в `monitor.mjs`.

## Как устроено

- **Данные:** JSON API табло `https://pulkovoairport.ru/api/?type=departure&when=0|1` (сегодня/завтра по Москве).
  Статус считается так же, как на сайте: «Регистрация 27-32», «Идет посадка», «Отправлен в …» и т.д.
- **Запуск:** GitHub Actions. Каждый запуск работает ~9 минут: слушает команды бота (long polling)
  и проверяет табло раз в минуту. В конце запуск сам ставит следующий в очередь (`workflow_dispatch`),
  пока рейс не улетел. Cron каждые 5 минут — запасной вариант (GitHub выполняет его с задержками).
  Ручной запуск: `Actions → Flight monitor → Run workflow`.
- **Состояние** хранится в `state.json` и коммитится только при изменениях.
  Список подписчиков в нём зашифрован (AES-256-GCM, ключ выводится из токена бота).
  После смены токена подписчики начинаются заново (остаётся только владелец).

## Настройка

Секреты репозитория:

```sh
gh secret set TELEGRAM_TOKEN
gh secret set TELEGRAM_CHAT_ID   # владелец
```

Необязательные переменные репозитория (`gh variable set ...`):

- `FLIGHT_NUMBER` — номер рейса, по умолчанию `WZ 709`;
- `FLIGHT_DATE` — дата вылета `YYYY-MM-DD` по Москве; если не задана, отслеживается ближайший рейс.

## Локальный запуск

```sh
DRY_RUN=1 node monitor.mjs   # одна проверка, сообщения печатаются вместо отправки
```

Нужен Node.js 18+, зависимостей нет.
