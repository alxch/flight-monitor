# flight-monitor

Telegram-бот [@provozhaem_elyu_bot](https://t.me/provozhaem_elyu_bot): следит за рейсом на табло аэропорта Пулково —
[вылета](https://pulkovoairport.ru/passengers/departure/) или [прилёта](https://pulkovoairport.ru/passengers/arrival/) —
и присылает изменения всем подписчикам.

По умолчанию — рейс **WZ 709 25.09 в 07:40, Санкт-Петербург → Батуми** (Red Wings).
Владелец меняет рейс и дату командой `/flight`.

Бот рассчитан на поездки на несколько дней: его включают под поездку, и он сам останавливается,
когда Эля вернулась.

## Новая поездка

1. Включить бота:
   ```sh
   gh workflow enable monitor.yml -R alxch/flight-monitor
   gh workflow run monitor.yml -R alxch/flight-monitor
   ```
2. Отправить боту рейс туда: `/flight <номер> <дата>`, например `/flight WZ 709 25.09`.
   Подписчики остаются с прошлой поездки; новым — ссылка https://t.me/provozhaem_elyu_bot.
3. За 3,5 часа до вылета бот напомнит владельцу вызвать такси.
4. После вылета — рейс обратно: `/flight <номер> <дата>` (через сутки бот напомнит).
5. После прилёта бот сам остановится. Выключить раньше: `gh workflow disable monitor.yml -R alxch/flight-monitor`.

## Функции

### Для всех подписчиков

| Что | Как работает |
|---|---|
| `/start` | Подписка. Ответ: «✅ Вы подписаны на уведомления», текущий статус рейса, «/stop — отписаться». |
| `/stop` | Отписка. |
| Любое другое сообщение | Ответ с текущим статусом рейса. |
| Уведомления об изменениях | Список изменений («было → стало») и полная строка рейса. |
| 🚨 Будильник при задержке или отмене | См. ниже. |
| Финальное сообщение | «🛫 …вылетел. Хорошего полёта!» или «🛬 …прибыл. С возвращением!». |
| Смена рейса | «🔄 Теперь слежу за рейсом …»; если рейса ещё нет на табло — сообщит, когда появится. |
| Проблемы с табло | «Табло недоступно» / «рейс не найден» — один раз, и ещё раз, когда всё восстановится. |

Что отслеживается:

- **Вылет:** статус (как на сайте: «Регистрация 27-32», «Идет посадка, выход 12», «Посадка закончена»,
  «Отправлен в …», «Задержан», «Отмена»), расчётное время, стойки регистрации, начало и конец регистрации,
  выход, начало и конец посадки, уход со стоянки, фактический вылет, самолёт и борт.
- **Прилёт:** статус («Ожидается», «В полёте» — после вылета из пункта отправления, «Задержан», «Прибыл»),
  вылет из пункта отправления, расчётное и фактическое время прилёта, лента выдачи багажа.

### 🚨 Будильник

Критичные события рассылаются как будильник: сообщение с кнопкой **«✅ Понятно»** приходит каждую минуту,
10 раз, пока получатель не нажмёт кнопку. Каждый повтор заменяет предыдущий (в чате одно сообщение,
звук уведомления — каждый раз). Кнопка останавливает повторы только для нажавшего.
Активных будильников может быть несколько — у каждого своя кнопка.

- **Задержка или отмена** — всем подписчикам: статус стал «Задержан», расчётное время вылета/прилёта
  сдвинулось на более позднее (позже расписания) или рейс отменён.
  «🚨 Рейс WZ 709 25.09 в 07:40, Санкт-Петербург → Батуми задержан! Вылет ожидается в 09:10 (по расписанию 07:40).»
- **🚕 Такси** — только владельцу, за 3,5 часа до вылета рейса «туда» (регистрация открывается за ~3 часа,
  дорога ~40 минут): «Пора вызывать Эле такси! … Регистрация: 04:40–06:40. Лучше быть в Пулково к 05:00.»

Будильник снимается сам после 10 повторов, после вылета/прилёта или при смене рейса.

### Для владельца (`TELEGRAM_CHAT_ID`)

Команды видны в меню только владельцу:

- `/flight WZ 710 28.09` — сменить рейс и дату; `/flight WZ 710` — ближайший рейс (сегодня/завтра);
  `/flight` — текущий рейс и справка. Дата: `28.09`, `28.09.2026`, `2026-09-28`, `сегодня`, `завтра`.
- `/subscribers` — список подписчиков с именами и @username (отписавшихся нет).

Уведомления владельцу:

- «👤 Новый подписчик: Имя (@username)» — при каждой новой подписке;
- 🚕 будильник «Пора вызывать Эле такси»;
- «🔔 Не забудь поставить обратный рейс» — через сутки после вылета, если не было `/flight`;
- «🛑 Бот остановлен» — при автоостановке, с командами для повторного включения.

### Направление: провожаем или встречаем

Рейс ищется на обоих табло. Из Петербурга — «Провожаем Элю ✈️ Санкт-Петербург → Батуми»,
в Петербург — «Встречаем Элю ✈️ Батуми → Санкт-Петербург».

### Профиль бота

Скрипт сам обновляет под текущий рейс и направление:

- имя: «Провожаем Элю · WZ 709 25.09 → Батуми» / «Встречаем Элю · WZ 710 28.09 Батуми → СПб»;
- короткое описание (превью ссылки);
- описание «What can this bot do?» (видно до нажатия Start) со строкой «Сейчас: <статус> (на ЧЧ:ММ МСК)».

Вручную (через Bot API) заданы аватар — самолёт без номера рейса — и меню команд.

### Автоостановка

Чтобы не держать GitHub Actions включённым без дела, бот останавливается сам и отключает workflow:

- после прилёта рейса в Петербург (задача выполнена);
- если после завершённого рейса 5 дней не было `/flight`.

Включить снова: `gh workflow enable monitor.yml` и `gh workflow run monitor.yml` (см. «Новая поездка»).

### Тексты

- Дата рейса указывается везде, где упоминается номер: «WZ 709 25.09 в 07:40, Санкт-Петербург → Батуми».
- Вводный текст («Провожаем Элю… Я слежу за рейсом…») — только в описании бота, не в сообщениях.
- Названия городов не склоняются («Санкт-Петербург → Батуми»), чтобы тексты были правильными для любого рейса.
  Имя задано константами `PERSON` («Элю») и `PERSON_DAT` («Эле») в `monitor.mjs`.

## Как устроено

- **Данные:** JSON API табло `https://pulkovoairport.ru/api/?type=departure|arrival&when=0|1` — все рейсы
  за сегодня/завтра по Москве (параметр `col` отдаёт только ближайшие N рейсов и не используется).
  WAF сайта пропускает только запросы с браузерным User-Agent. Статусы вылета вычисляются так же,
  как в JavaScript сайта (`script.js`); «В полёте» для прилёта — добавлено ботом.
- **Запуск:** GitHub Actions. Каждый запуск работает ~9 минут: слушает Telegram (long polling) и проверяет
  табло раз в минуту. В конце запуск сам ставит следующий в очередь (`workflow_dispatch`, 5 попыток).
  Cron каждые 5 минут — запасной вариант (GitHub выполняет его с задержками и может пропускать).
- **Состояние** — `state.json`, коммитится только при изменениях: текущий рейс, настройка из `/flight`,
  подписчики, активные будильники, профиль бота. Подписчики и получатели будильников зашифрованы
  (AES-256-GCM, ключ выводится из токена бота); после смены токена подписчики начинаются заново.

## Настройка

Секреты репозитория:

```sh
gh secret set TELEGRAM_TOKEN
gh secret set TELEGRAM_CHAT_ID   # владелец
```

Необязательные переменные репозитория (`gh variable set ...`) — рейс по умолчанию, пока не задан через `/flight`:

- `FLIGHT_NUMBER` — номер рейса, по умолчанию `WZ 709`;
- `FLIGHT_DATE` — дата `YYYY-MM-DD` по Москве; если не задана, отслеживается ближайший рейс.

## Локальный запуск

```sh
DRY_RUN=1 node monitor.mjs   # одна проверка, сообщения печатаются вместо отправки
```

Для проверки команд без Telegram: `TEST_UPDATES='[{"update_id":1,"message":{...}}]'`,
ускорить будильник: `ALARM_INTERVAL=1` (секунды). Нужен Node.js 18+, зависимостей нет.
